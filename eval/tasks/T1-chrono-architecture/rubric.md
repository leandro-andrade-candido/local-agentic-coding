# T1 rubric: chrono architecture (`ARCHITECTURE.md`)

Written before the runs, from the code at the pinned commit (chrono-node 2.10.3).
Each item is worth 1 point if the document states it **correctly and specifically** (with the real name of the file, class or function). A vague or wrong description is worth 0.
**T1 success: grade >= 7.** Relevant false claims (invented files or classes) cost 1 point each, up to 3; record them in `notes`.

| # | Fact | What must appear |
|---|---|---|
| 1 | **Entry point and API.** `src/index.ts` re-exports the languages as namespaces (`chrono.en`, `chrono.pt`, `chrono.de` ...) and exposes the `parse`/`parseDate` shortcuts and the `casual`/`strict` instances, which are the English ones (`en.casual`/`en.strict`). | `src/index.ts`, `parse`/`parseDate` shortcuts, English as the default, languages as namespaces. |
| 2 | **Orchestration.** The `Chrono` class (`src/chrono.ts`) holds a list of parsers and a list of refiners (`Configuration`). `parse()` creates a `ParsingContext`, runs every parser, sorts the results by position in the text and then applies the refiners in sequence, each receiving the previous one's list. `parseDate()` returns the date of the first result. | `Chrono`, parsers -> sorting -> refiners in sequence. |
| 3 | **Parser contract.** `Parser` interface with `pattern(context)` (a RegExp) and `extract(context, match)`; `Chrono.executeParser` walks the matches in the text and, if `extract` returns `null`, advances 1 character and tries again. `extract` can return `ParsingComponents`, `ParsingResult` or a plain components object. | `pattern`/`extract` and the match loop. |
| 4 | **Word-boundary base class.** Most parsers extend `AbstractParserWithWordBoundaryChecking` (`src/common/parsers/AbstractParserWithWordBoundary.ts`), which prefixes `(\W|^)` to the pattern, implements `innerPattern`/`innerExtract` and caches the compiled pattern. | Class name and the role of `innerPattern`/`innerExtract`. |
| 5 | **Result model.** `src/results.ts`: `ParsingResult` (index, text, start, end, refDate) and `ParsingComponents`, which separates known values (`assign`, `knownValues`) from implied ones (`imply`, `impliedValues`); `isCertain()` says whether the component was stated in the text. `ReferenceWithTimezone` represents the reference date with a time zone. | Known vs implied distinction (assign/imply/isCertain) and `ParsingResult` with start/end. |
| 6 | **Refiners.** They post-process the list: merge date and time (`AbstractMergeDateTimeRefiner`), merge "X to Y" ranges into start/end (`AbstractMergeDateRangeRefiner`), remove overlaps (`OverlapRemovalRefiner`), apply `forwardDate` (`ForwardDateRefiner`), extract the time zone (`ExtractTimezoneAbbrRefiner`/`ExtractTimezoneOffsetRefiner`) and filter unlikely formats (`UnlikelyFormatFilter`). The order matters and some run more than once. | At least three real refiners with the correct role, and the remark that the order matters. |
| 7 | **Configurations.** `src/configurations.ts` `includeCommonConfiguration` adds the `ISOFormatParser` and the common refiners. Each language builds `createConfiguration(strictMode, littleEndian)` and `createCasualConfiguration()`; casual adds informal parsers ("today", "tomorrow", "now"...), strict does not. `littleEndian` decides day/month in slash dates (`en.GB` vs `en.US`). | casual vs strict and `includeCommonConfiguration` (or equivalent). |
| 8 | **Language organization.** `src/locales/<language>/` with `constants.ts` (dictionaries of weekdays, months, numbers, time units and functions such as `parseDuration`), `parsers/`, `refiners/` and `index.ts` (configuration and shortcuts). Languages have uneven coverage (`pt` is partial). To extend, you create a parser/refiner and register it in the language configuration. | `locales/` structure with `constants.ts`/`parsers`/`refiners`/`index.ts` and how to extend. |
| 9 | **Time zone and options.** `ParsingOption` (`src/types.ts`) has `forwardDate`, `timezones` (custom abbreviation map) and `debug`. `src/timezone.ts` has `TIMEZONE_ABBR_MAP` with daylight saving time rules; the reference can be a `Date` or a `ParsingReference` with `timezone`. | At least two real options and the time zone map in `timezone.ts`. |
| 10 | **Utilities and tests.** `src/calculation/` (`duration.ts` with `addDuration`, `weekdays.ts`, `years.ts` for the implied year, `mergingCalculation.ts`) and `src/utils/pattern.ts` (`matchAnyPattern`). Tests in `test/` (one directory per language), jest with `ts-jest`, the `testSingleCase`/`testUnexpectedResult` helpers and the `toBeDate` matcher in `test/test_util.ts`. | `src/calculation` + `test/test_util.ts`/`testSingleCase` + jest. |
