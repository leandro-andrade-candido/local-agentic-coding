## Problem found and fixed

The health check read the output limit from `/props`, which shows `n_predict=-1` even with `-n 32768`; the value only shows up in the effective request. The check now makes a real request with `response_fields`.

The first version of this fix did not limit generation and hit the timeout while the CPU was contended. The final version ends the request at the first word, using stop words, and generates 2 tokens.

- the reasoning effort level each agent sends.
